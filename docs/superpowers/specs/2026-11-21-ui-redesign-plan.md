# LeoChat 界面重设计方案

> 日期：2026-11-21　状态：方案，待实施
> 参考：**dsh**（`C:\code\deepseek-harness\packages\client\ui-*`，主要参考）、**Codex App**（公开资料，次要参考）

## 1. 为什么要改

现状截图（2026-11-21，1440×900）里的问题：

| # | 问题 | 现象 |
|---|---|---|
| 1 | 导航占地、层级多 | 左边一条图标栏（聊天 / MCP / 设置）+ 第二栏会话列表，两栏合计约 280px；MCP 和设置是整页替换聊天，切过去就看不到对话 |
| 2 | 顶栏杂乱 | "简 / 专 / CN / 邮件 / GitHub" 五个小图标常驻，和对话无关 |
| 3 | 一个回合被拆成多张卡片 | 每一步模型输出都是一张灰底卡片，顶部固定有"MD / 复制"工具条和"思考过程 · 思考完成"一行，哪怕没内容；工具调用是一颗绿色胶囊"bash [完成] 详情"。一次 bash 调用产生两张卡片 |
| 4 | 过程和结果混在一起 | 思考、工具调用、最终回答的视觉分量一样，读者找不到答案在哪 |
| 5 | 输入区的状态条各管各的 | 目标条、提醒条、收件箱各自一条横幅；工具栏里放着"清空"这种破坏性操作 |
| 6 | 没有右侧面板 | 工具输出、目标进度、定时任务、收件箱都只能在对话流里找 |
| 7 | 设置和 MCP 页粗糙 | "通用"页只有一个按钮；MCP 环境列表挤成竖排文字，服务器卡片大量"暂无描述" |
| 8 | 手机端 | 只做过引导页，主界面没有适配 |

## 2. 参考：dsh 和 Codex 的做法

**dsh 的 Web 界面**（全部来自各包 README）：

- `ui-layout`：**三栏 AppFrame**。左侧边栏、中间对话、右侧是"边缘停靠面板"的轨道；空间不够时右栏先让位，中间不缩。
- `ui-sidebar`：**一条侧边栏**，顶部是品牌 + 新建会话 + 折叠按钮（折叠成 56px 窄条），中间是工作区 / 会话列表，**设置固定在最底部**。
- `ui-workspace`：会话按工作区分组（或平铺），行内有管理操作。
- `ui-chat`：**"工作细节模式"**控制思考过程和过程行的显示，**无论哪种模式都不隐藏最终回答**；Verbose 模式下，已完成回合的过程行保持展开。
- `ui-tool`：工具调用按"整次调用树"渲染，每种工具有自己的原子卡片，没注册的工具用通用卡片。
- `ui-goal`：目标是**输入框上方的上下文条**，可以编辑、暂停、恢复、清除。
- `ui-plan` / `ui-model-selection` / `ui-permission-presets`：计划模式、模型、权限预设都是**输入框上的小控件**（chip / seat），也都能用 `/` 命令打开。
- `ui-input-trigger` / `ui-commands`：`/` 和 `@` 在光标处触发分组候选菜单。
- `ui-jobs`：会话头部有后台任务列表，可以展开看流式输出。
- `ui-schedule`：跨会话的任务管理 + 当前会话的提醒目录。
- `ui-sidebar-right`：**右侧边栏是按会话停靠的标签面板**，标签类型可以注册：文件树、终端、浏览器、文档预览、改动审查（`ui-deliverables`）。
- `ui-deliverables`：回合结束时出现"改动的文件 / 交付物"卡片，点开在右栏对比。

**Codex App**（公开资料，细节有限）：

- 线程按项目分组；右侧面板看 diff、做 PR 审查（行内评论、按块暂存或回滚）。
- **任务侧栏**：显示计划步骤和进度、用到的资料、产生的产物、总结，**作为翻工具调用流的替代**。
- 多个终端标签；权限选择器在输入区。

两者的共同点：**对话流只讲结果，过程收起来；状态和产物放到侧栏；控件都长在输入框上。**

```
┌──────────────┬───────────────────────────────────────────┬───────────────────┐
│ ◧ LeoChat  ✎ │  会话标题                      ⋯  [任务 ▸] │  任务 · 工具 · 文件 │
│              │                                           │                   │
│ 今天          │                  你：搜索黄仁勋的近况 ┐     │  目标              │
│  ● 搜索黄仁勋… │                                         │  列出 1–300 质数   │
│    写一篇 1500… │  ▸ 已完成 · 联网搜索 2 次 · 8 秒          │  第 2/256 轮 · 完成│
│ 昨天          │                                           │                   │
│    请用 sched… │  他确实已在 2026 年 11 月……（正文，无底卡）  │  定时提醒          │
│    目标：列出… │  ① Nvidia CEO steps down  ② 黄仁勋辞职…    │  60 秒后 · 待触发  │
│              │                                 ⧉ ↻ 👍    │                   │
│              │                                           │  收件箱 (1)        │
│              │ ┌───────────────────────────────────────┐ │  · 下一步插入的消息 │
│              │ │ 🎯 目标：列出 1–300 质数 · 第 2 轮   ⏸ ✕ │ │                   │
│              │ ├───────────────────────────────────────┤ │                   │
│              │ │ 输入消息，/ 命令，@ 引用工具…            │ │                   │
│ ──────────── │ │ [deepseek-flash ▾] [询问 ▾] [联网] [⊕]  ➤│ │                   │
│ ⚙ 设置        │ └───────────────────────────────────────┘ │                   │
└──────────────┴───────────────────────────────────────────┴───────────────────┘
```

- **左**：一条侧边栏（约 260px，可折叠成 56px 窄条）。会话按"今天 / 昨天 / 更早"分组；底部固定"设置"。MCP 不再是一级导航，移进设置。
- **中**：对话。顶栏只有会话标题、更多菜单、右栏开关。语言、邮件、GitHub 等全部移进设置。
- **右**：可开关的停靠面板，**默认收起**（2026-11-21 用户在视觉伴侣里选定）。会话里有目标、定时提醒、排队消息或待审批操作时，顶栏的"任务"按钮亮起并显示数量，点开才展开；手动打开后按会话记住。第一版两个标签：**任务**（目标、定时提醒、收件箱、后台任务）和**工具**（选中某次工具调用时，看它的完整输入和输出）。窗口宽度不足 1100px 时，右栏改为覆盖在对话上方。

## 4. 对话的呈现

一个**回合** = 一条用户消息 + 一次完整的助手回应（包括中间所有步骤）。

```
                                             ┌──────────────────────────┐
                                             │ 请用 bash 执行 echo …      │  ← 用户：右侧浅色气泡
                                             └──────────────────────────┘
▸ 已完成 · 运行 1 条命令 · 3 秒                                           ← 过程行（默认收起）
  （展开后）
  ┊ 思考：用户要求执行命令并原样返回……
  ┊ $ echo leochat-full-access        ✓ 0.2s   [在右栏查看]
命令执行完成，输出为：                                                    ← 正文：无底卡、全宽
┌ plaintext ───────────────────────┐
│ leochat-full-access               │
└───────────────────────────────────┘
                                             ⧉ 复制  ↻ 重试  ⋯        ← 悬停时出现
```

- **正文不加底卡**，用全宽排版，和 dsh、Codex 一样。用户消息保持右侧浅色气泡。
- **过程：运行时展开时间线，完成后收成一行**（2026-11-21 用户在视觉伴侣里选定 B）。运行中按时间顺序显示思考和每一步工具调用（状态、耗时），当前步骤带转圈；回合结束后自动收成"已完成 · 4 步 · 8 秒"，点开可再看全部步骤。
- **工作细节模式**（按 dsh）：**简洁**（默认，已完成回合的过程行收起；运行中的回合展开）和**详细**（全部展开）。在设置里切换，也能用 `/details` 命令切换。最终回答在任何模式下都不隐藏。
- **工具调用行**：图标 + 一句话描述（命令本身、搜索词、文件名）+ 状态（运行中 / ✓ / ✗）+ 耗时；点"在右栏查看"看完整输入和输出。沿用 dsh 的做法：按工具名注册专用视图，未注册的走通用视图。bash、web_search、文件读写、MCP 工具、界面操作工具、目标和定时工具各给一个专用视图。
- **审批**：需要批准的工具调用，在过程行里**就地展开成审批卡片**（命令、理由、允许一次 / 拒绝），并在输入框上方提示"有 1 个操作等待你确认"。
- **引用**：联网搜索的来源显示成正文末尾的一排编号小标签，悬停显示标题和域名。
- **操作**：复制、重试、反馈放在回合末尾，悬停时出现；去掉每张卡片顶部常驻的"MD / 复制"。

## 5. 输入区

- **上下文条**（按 dsh 的 `ui-goal`；2026-11-21 用户在视觉伴侣里选定 A，三选一中的"顶上一条提示"）：输入框上方只留**一条**，显示当前最重要的状态，优先级：等待审批 > 目标进行中 > 收件箱有排队消息 > 定时提醒。多项时右侧显示"+2"，点开到右栏"任务"标签。现在分开的目标条、提醒条、收件箱条合并到这里。
- **输入框下方的控件**（chip）：模型、权限预设（询问 / 完全信任）、联网开关、附件（⊕）。MCP 工具数量移到 `@` 菜单和设置里。
- **"清空"从工具栏去掉**，改为 `/clear` 命令和会话的"⋯"菜单，并且要二次确认（按 dsh：有不可逆副作用的操作只留明确的入口）。
- `/` 和 `@` 保持现有功能，菜单改成分组样式：命令 / 工具 / 文件。

## 6. 设置

- 设置页从侧边栏底部进入，**覆盖中间和右侧区域**，左侧边栏保留，能直接点回会话。
- 分组：通用（语言、主题、工作细节模式、重新运行引导）· 模型（提供商、密钥、默认模型、联网）· 权限（默认预设、AGENTS.md 路径）· **MCP**（服务器、工具、资源、提示词、环境）· 网络 · 关于（版本、GitHub、反馈邮箱）。
- MCP 服务器卡片：没有描述时不显示"暂无描述"，改显示传输方式和工具数量；环境检测改成表格（名称 · 状态 · 安装命令）。

## 7. 手机端

- 右栏变成从底部滑出的面板。
- 输入框下方的控件折叠成一个"⋯"按钮。

### 9.1 实施中做的决定和 dsh 出处（2026-11-23 逐项核对）

规则（用户的目标）：要决定时先看 dsh 怎么做；dsh 的做法没问题就照做、不问；dsh 不完善或不适用时才问用户。

| 决定 | dsh 出处 | 结论 |
|---|---|---|
| 过程收起、最终回答永不隐藏 | `client/ui-chat` README：Work-details 模式折叠已完成回合，不隐藏最终回答 | 照搬规则；dsh 有 4 档（Compact/Standard/Detailed/Verbose），按 §9 只做"简洁/详细"2 档 |
| `/details` 命令 | dsh 没有这个命令，只在设置里切换 | 计划 §4 里我们自己加的入口，设置里同样能切 |
| `/` 命令菜单分组 | `client/ui-commands`：选项可带 `group`，组有标题、按首次出现排序 | 照搬 |
| 上下文条（目标等） | `client/ui-goal`：目标是输入框上方的条 | 照搬；合并多项、优先级由用户在视觉伴侣里定（§9） |
| 附件 | `attachment/attachment`、`attachment-local`：内容寻址存本地、日志只存引用、读时校验 | 照搬存储规则；普通文件 dsh 只给路径，LeoChat 默认没有文件工具，改用 DeepSeek Files（不适用处的替代，见 P3b） |
| 附件的界面 | `client/ui-attachment`：待发送附件是一条不换行的横条（64px 高：图片 64px 方块，文件 240px 卡片带大写扩展名和大小；两端翻页箭头、隐藏滚动条、新加的滚到可见；上传中转圈、失败可重试；移除按钮悬停/聚焦出现、触屏常显）；拖文件时铺满窗口的提示；消息里单张图按长边 240px、多个附件时 64px 方块和 240×64 卡片；灯箱 Esc/遮罩/关闭按钮关闭并把焦点还给缩略图 | 照搬（2026-11-24 审计时发现原来是会换行的小标签、没有拖放提示和灯箱，已改） |
| 来源引用 | dsh 的 README 里没有找到来源的展示规则 | 没有可参照的 dsh 做法，按计划 §4 用编号小标签 |
| 右栏 | `client/ui-sidebar-right`：每会话一个、默认收起、顶栏角上的按钮是唯一入口、localStorage 按会话保存 | 照搬；第一版不做分屏、浮动、拖拽宽度（dsh 的 dockkit） |
| 右栏宽度与窄屏 | `client/ui-layout`：首开 45% 视口，之后用用户拖出的宽度（窗口共用、刷新后回到默认），上限 70%；对话区至少 400px，先缩到 300px，还不够就收起右栏；768px 以下全屏 | 照搬（2026-11-24 由"固定 360px + 窄屏覆盖"改回 dsh 的规则，`dockWidthFor` 有单元测试） |
| 侧边栏窄窗口自动收起 | `client/ui-layout`：窄于 1024px 自动收成 56px 窄条；打开右栏会收起手动展开的侧边栏 | 照搬（核对时发现漏了，已补，`e2e/layout.spec.ts`） |
| 手机（768px 以下）侧边栏 | `client/ui-layout` 的"已知限制"：极窄窗口仍保留 56px 窄条，中间可能不足 400px | dsh 自己列为限制，不算完善 → 按计划 §7 用抽屉；**2026-11-24 用户确认保留抽屉** |
| 会话"⋯"菜单 | `client/ui-sidebar-right`：会话顶栏有"More"按钮，与右栏按钮相邻 | 照搬位置；菜单内容（重命名、删除）按计划 §5 |
| 重命名就地编辑 | dsh README 里没有找到会话重命名的描述 | 没有可参照的 dsh 做法；选择最小的方案（标题就地变输入框），不涉及不可逆操作 |

| 工具审批的位置 | `client/ui-approval`：审批面板接管输入框（原输入框留在下面、草稿不丢）；详情获得焦点后 Enter 允许、Esc 拒绝；只接受一次回答 | 照搬（2026-11-24 由"过程里的审批卡片 + 上下文条提示"改回 dsh）。不同之处：多一个"本次会话允许"——dsh 的长期权限在宿主的权限包里，LeoChat 没有对应的包；**2026-11-24 用户确认保留** |
| 工具调用的展示 | `client/ui-tool`：按工具名注册专用视图，未注册的用通用卡片 | 照搬（P2 的 `tool-views.tsx`） |
| 回答后的操作 | `client/ui-message-feedback`：回答操作栏里有赞 / 踩，打开反馈对话框记录 | 只做了复制和编辑重发；LeoChat 没有收集反馈的后端，暂不做 |
| `@` 菜单 | `client/ui-reference`：`@` 引用工作区的文件、文件夹、会话 | LeoChat 没有工作区，没有可引用的对象，暂不做 |
| 流式正文的显示节奏 | dsh 收到多少显示多少，没有平滑 | 网络不稳时一段一段地跳（实测：前端没有额外攒批，是数据在网络上积压后成批到达）→ 问了用户，**2026-11-25 用户选择加平滑**：按均匀速度逐字显示，积压越多越快（约 0.3 秒追平），结束时立刻显示全部（`useSmoothText`） |
| 破坏性操作要确认 | 计划 §9 已按 dsh 定：不可逆副作用只留明确入口 | 删除对话 / `/clear` 都先确认 |

## 10. 不在这次范围内

文件树、终端、浏览器标签（dsh 有，LeoChat 目前没有对应能力）；会话分组到"工作区"（LeoChat 现在没有工作区概念，先按日期分组）；Codex 式的 diff 审查（LeoChat 不改代码仓库）。

  - 会话日志里只存引用 `attachment:<id>`，不存 base64、不存路径；每轮发请求前由 `withAttachments` 换成内容：能看图的模型 → base64 图片；原生 DeepSeek 的文件 → 上传到 Files API 换 `file_id`（PDF/Word/PPT 用 text_recognition，其它用 user_data），按账号缓存；读不了时换成一行说明，不悄悄丢掉。
